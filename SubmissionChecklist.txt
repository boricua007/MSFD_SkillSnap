Submission Checklist (Part 4 - Caching and State Management)
    In-memory caching implemented in the API ✔️
        IMemoryCache is registered in Program.cs and project results are cached
        using a sliding expiration of 5 minutes and an absolute expiration of
        20 minutes.

    Query performance improvements applied ✔️
        The projects query uses AsNoTracking and projects directly into a flat
        ProjectDto response, avoiding unnecessary entity tracking and navigation
        graph serialization.

    Skill DTO added for consistent API contracts ✔️
        SkillDto is stored in the API DTOs folder, and SkillsController maps
        between the DTO and the EF Skill entity for GET and POST requests.

    Blazor state management enabled ✔️
        UserSessionService stores the current user, role, and selected project
        for reuse across the Blazor client.

    Performance verified through Swagger and runtime logging ✔️
        GET /api/projects was executed twice through Swagger. The first request
        logged Cache miss and took 524 ms; the second logged Cache hit and took
        0 ms. Both requests returned HTTP 200 successfully.

    Copilot suggestions used and applied ✔️
        Copilot guidance was used to implement caching, DTO response shaping,
        query optimization, relationship fixes, and runtime verification.
